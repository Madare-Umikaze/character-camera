# Character Camera：テスト計画

本書は、全機能のテスト計画を定義します。
テストは「単体テスト」と「実機テスト」に区別します。

- **単体テスト**：Vitest（node 環境）で自動実行する。DOM・WebGL・カメラに依存しない純粋ロジックが対象。
- **実機テスト**：スマートフォン実機のブラウザで手動確認する。ブラウザ API、GPU 描画、タッチ操作、保存挙動が対象。

実装は Phase ごとに進めるため、各項目は該当 Phase で実施します。結果は本書の末尾の記録欄に追記します。

## 1. テストの分類方針

| 観点 | 単体テスト | 実機テスト |
|---|---|---|
| 実行方法 | `npm run test` | 実機ブラウザで手動操作 |
| 対象 | 数学・変換・検証ロジック・状態遷移 | カメラ、WebGL2、タッチ、ファイル選択、保存、PWA |
| 環境 | node | iOS Safari、Android Chrome ほか |
| 自動化 | する | しない（チェックリストで管理） |

### 単体テストの方針

- 純粋関数として切り出せるロジックは、必ず単体テストを書く。
- ブラウザ API に依存する部分は、判定・変換ロジックを純粋関数に分離して、その部分をテストする。
- DOM が必要なテストが出た場合は、テスト環境用パッケージ（例：`jsdom`）の導入を、依存関係の追加ルールに従って提案する。
- テストファイルは `tests/` に置き、`*.test.ts` の命名にする。
- 数値計算は、`toBeCloseTo` で許容誤差を指定して比較する。

### 実機テストの対象環境

| 区分 | 環境 | 備考 |
|---|---|---|
| 必須 | iPhone（iOS Safari） | カメラ・保存の挙動が独特なため重点確認 |
| 必須 | Android（Chrome） | |
| 推奨 | PC ブラウザ（Chrome、Safari、Firefox） | 開発時の確認用 |
| 推奨 | 画面サイズの異なる複数端末 | ノッチ、セーフエリア、縦横回転 |

具体的な OS バージョン・端末名は、実機確認を行う時点で記録欄に記入する。
