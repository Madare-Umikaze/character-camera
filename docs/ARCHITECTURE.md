# Character Camera：アーキテクチャ設計書

本書は、各モジュールの役割・依存関係・データの流れを定義します。
実装は Phase ごとに進めるため、本書の内容のうち、未実装の部分は「設計方針」です。実装時に判明した事項は、該当 Phase で本書を更新します。

## 1. 設計の基本方針

1. **レイヤー分離**：カメラ映像は背景レイヤー、キャラクター画像は前景レイヤーとして独立して扱う。
2. **変形の適用範囲**：回転・拡大縮小・射影変換・台形補正・四隅自由変形は、**キャラクター画像のみ**に適用する。カメラ映像には適用しない。
3. **ブラウザ内完結**：すべての処理はブラウザ内で行い、画像・映像を外部へ送信しない。サーバーサイド処理とデータベースは存在しない。
4. **責務の分離**：UI、カメラ制御、画像処理、描画、保存を別モジュールにする。
5. **純粋ロジックの分離**：数学的な計算は DOM・WebGL に依存させず、単体テスト可能にする。

## 2. モジュール構成

```text
src/
├── types/       共通の型定義
├── transform/   変形の数学（純粋関数）
├── camera/      カメラ制御
├── image/       画像読み込み
├── filters/     フィルター・色覚シミュレーションの定義
├── rendering/   描画（WebGL2 / Canvas）
├── capture/     撮影・保存
├── ui/          UI 部品・イベント処理
├── main.ts      エントリーポイント（各モジュールの組み立て）
└── style.css    グローバルスタイル

public/shaders/  GLSL シェーダー
tests/           単体テスト
docs/            設計書・テスト計画
```

## 3. 各モジュールの役割

### 3.1 types/

- 役割：モジュール間で共有する型（キャラクターの変形状態、四隅の座標、フィルター種別、カメラ状態など）を定義する。
- 実行時ロジックは持たない（Phase 0 の `app.ts` は動作確認用の例外）。
- 他のどのモジュールにも依存しない。

### 3.2 transform/

- 役割：キャラクター画像の変形に関する計算を提供する。
  - 位置・拡大縮小・回転から変換行列を作る
  - 四隅の座標から射影変換行列（ホモグラフィ）を求める
  - 横方向・縦方向の遠近感パラメータを、四隅の座標または行列へ変換する
  - 画面座標とキャラクター座標の相互変換（タッチ操作のヒットテスト用）
- 行列計算には gl-matrix を使う。
- DOM・WebGL・カメラに依存しない純粋関数とする。
- 依存先：`types/`、`gl-matrix`

### 3.3 camera/

- 役割：`navigator.mediaDevices.getUserMedia` によるカメラの起動・停止・前面背面の切り替え、およびエラーの分類（権限拒否、デバイスなし、使用中、非対応）。
- `MediaStream` を保持し、`HTMLVideoElement` へ接続する。
- 切り替え時やページ非表示時に、既存トラックを必ず `stop()` して解放する。
- 映像のピクセルを加工しない。
- 依存先：`types/`

### 3.4 image/

- 役割：ユーザーが選択したファイルを、描画可能な画像（`ImageBitmap` など）へ変換する。
  - ファイル種別・サイズの検証
  - 画像のデコードと、EXIF の向きの反映
  - 不要になった `ImageBitmap` と Object URL の解放
- 外部へのアップロードは行わない。
- 依存先：`types/`

### 3.5 filters/

- 役割：フィルター（白黒・ビビッド・セピアなど）と色覚シミュレーション（P型・D型・T型）の**定義**を提供する。
  - 各フィルターを、色変換行列やパラメータとして表現する
  - 種別と変換の対応表を持つ
- 変換の数値定義は純粋なデータ・関数として持ち、単体テスト可能にする。
- GPU 上での実際の適用は `rendering/` が行う。
- 依存先：`types/`

### 3.6 rendering/

- 役割：背景（カメラ映像）と前景（キャラクター画像）を画面に描画する。
  - WebGL2 コンテキストの生成・管理、コンテキスト消失への対応
  - シェーダーのロード・コンパイル（`public/shaders/`）
  - 映像フレームとキャラクター画像のテクスチャ管理
  - キャラクターへの変換行列の適用
  - フィルターの適用
  - 描画ループ（`requestAnimationFrame`）
- WebGL2 が使えない環境のためのフォールバック（Canvas 2D 等）を設けるかは、Phase 2 以降で判断する。
- 依存先：`types/`、`transform/`、`filters/`、`gl-matrix`

### 3.7 capture/

- 役割：撮影と保存。
  - 背景のみの画像生成（キャラクターを含めない）
  - 背景とキャラクターの合成画像の生成
  - `Blob` への変換と、端末への保存（ダウンロード、または Web Share API）
- 描画パスを背景のみ／合成で分けられるよう、`rendering/` の公開インターフェースを通じて画像を取得する。
- 依存先：`types/`、`rendering/`

### 3.8 ui/

- 役割：ボタン、スライダー、タッチ操作（ドラッグ・ピンチ・回転・四隅ハンドル）、エラー表示。
- ユーザー操作を、型付きの状態更新やコマンドに変換する。
- カメラや描画の内部実装を直接操作せず、公開インターフェースだけを使う。
- 依存先：`types/`、`transform/`（座標変換のみ）

### 3.9 main.ts

- 役割：各モジュールの生成・接続（組み立て）のみ。ロジックは持たない。
- すべてのモジュールに依存してよい唯一の場所とする。

## 4. 依存関係

矢印は「依存する」を表します（A → B：A は B を使う）。

```text
                      main.ts
        ┌──────┬────────┼────────┬─────────┬───────┐
        ▼      ▼        ▼        ▼         ▼       ▼
      ui/   camera/   image/  rendering/ capture/ filters/
        │      │        │      │  │  │      │         │
        │      │        │      │  │  └──────┼─────────┤
        │      │        │      │  │         │         │
        │      │        │      │  └─▶ transform/      │
        │      │        │      │         │            │
        └──────┴────────┴──────┴─────────┴────────────┘
                              ▼
                           types/
```

### 依存ルール

| モジュール | 依存してよい | 依存してはいけない |
|---|---|---|
| `types/` | なし | すべて |
| `transform/` | `types/`、`gl-matrix` | DOM、WebGL、`camera/`、`ui/` など |
| `camera/` | `types/` | `rendering/`、`capture/`、`ui/`、`image/` |
| `image/` | `types/` | `rendering/`、`capture/`、`ui/`、`camera/` |
| `filters/` | `types/` | `rendering/`、DOM |
| `rendering/` | `types/`、`transform/`、`filters/`、`gl-matrix` | `ui/`、`camera/`、`image/`、`capture/` |
| `capture/` | `types/`、`rendering/` | `ui/`、`camera/`、`image/` |
| `ui/` | `types/`、`transform/` | `rendering/`、`camera/`、`image/`、`capture/` の内部実装 |
| `main.ts` | すべて | （なし） |

- `rendering/` は `camera/` や `image/` を直接 import しない。映像要素（`HTMLVideoElement`）や `ImageBitmap` は、`main.ts` が引数として渡す。これにより、描画をカメラや画像読み込みから独立させる。
- `ui/` が他モジュールを操作する場合は、`main.ts` が関数やコールバックを注入する。
- 循環依存を作らない。

## 5. データの流れ

全体像：

```text
[カメラ] ──MediaStream──▶ <video> ──────────────────────┐
                                                        ▼
[ファイル] ──File──▶ image/ ──ImageBitmap──┐        rendering/
                                           ▼        ┌────────────────────────┐
[ui/] ──変形パラメータ──▶ transform/ ──行列──▶     │ 1. 背景を描画（無変形）│
                                                    │ 2. キャラクターを描画  │
[ui/] ──フィルター種別──▶ filters/ ──定義──▶       │    （行列を適用）      │
                                                    │ 3. フィルターを適用    │
                                                    └───────────┬────────────┘
                                                                ▼
                                                    画面（プレビュー）
                                                                │
[ui/] ──撮影操作──▶ capture/ ──────────────────────────────────┘
                       ▼
                     Blob ──▶ 端末へ保存（外部送信なし）
```

### 5.1 カメラ映像の取得

1. UI の操作（起動ボタン）を受けて、`camera/` が `getUserMedia` を呼ぶ。
2. 背面カメラは `facingMode: 'environment'`、前面カメラは `facingMode: 'user'` を指定する。
3. 取得した `MediaStream` を `<video>` 要素の `srcObject` に設定し、再生する（`playsinline` と `muted` を指定。iOS Safari の要件）。
4. 切り替え・停止時は、すべてのトラックを `stop()` してから再取得する。
5. エラー（権限拒否、デバイスなし、使用中）は種別に分類し、UI へ通知する。
6. 映像ピクセルには、この段階でも以降でも変形を加えない。

### 5.2 キャラクター画像の読み込み

1. UI の `<input type="file" accept="image/*">` で、ユーザーがファイルを選ぶ。
2. `image/` が、種別とサイズを検証する。
3. `createImageBitmap` でデコードする。EXIF の向きを反映する（`imageOrientation: 'from-image'`）。
4. 得られた `ImageBitmap` を `main.ts` 経由で `rendering/` に渡し、テクスチャ化する。
5. 差し替え時は、古い `ImageBitmap` とテクスチャを解放する。
6. ファイルの内容は、ブラウザの外へ送信しない。

### 5.3 画像変形

1. UI が、ユーザー操作を、型付きの変形状態に変換する。
   - 位置、拡大縮小、回転、透明度
   - 四隅の座標
   - 横方向・縦方向の遠近感
2. `transform/` が、変形状態から 3×3（または 4×4）の変換行列を計算する。
   - 四隅から射影変換行列（ホモグラフィ）を求める
   - 遠近感のパラメータは、四隅の座標へ変換して、同じ経路で処理する
3. 計算結果は純粋なデータ（行列）であり、描画の副作用を持たない。
4. この行列は、**キャラクターの描画にのみ**使う。背景の描画には渡さない。

### 5.4 描画

1. `rendering/` は、描画ループの各フレームで次の順に処理する。
   1. **背景**：`<video>` の現在のフレームをテクスチャとして、画面全体に描画する。
   2. **前景**：キャラクターのテクスチャを、5.3 の行列で変形して、背景の上に重ねる。透明度を反映する。
2. 背景には、画面への表示に必要な「アスペクト比を保った拡大（cover 表示）」だけを適用する。
   これは表示領域へのフィット処理であり、映像内容の回転・射影変換・台形補正は行わない。
3. キャラクターのクリッピングや座標は、画面座標系に統一する。
4. WebGL2 のコンテキスト消失・復元に対応する。
5. ページが非表示のときは、描画ループを停止する。

### 5.5 フィルター

1. `filters/` が、フィルター種別（白黒・ビビッド・セピア、P型・D型・T型）に対応する色変換の定義を提供する。
2. `rendering/` が、その定義をシェーダーの uniform として設定し、GPU 上で適用する。
3. 適用範囲の方針：
   - プレビューでは、背景とキャラクターを合成した結果に対して適用する想定。
   - 保存画像にフィルターを含めるか、背景のみの保存にフィルターを適用するかは、**Phase 3 の指示に従って確定**し、確定後に本書を更新する。
4. 色覚シミュレーションは見え方の確認用であり、元画像を書き換えない。

### 5.6 撮影・保存

1. UI の撮影操作を受けて、`capture/` が保存対象に応じた画像を生成する。

| 保存の種類 | 内容 | 禁止事項 |
|---|---|---|
| 背景のみ | カメラ映像のフレームだけ | キャラクターを**絶対に含めない** |
| 合成画像 | 背景＋変形後のキャラクター | （なし） |

2. 背景のみの保存は、キャラクターを描画するパスを通さずに生成する。描画後の画面をキャプチャして、キャラクターを後から消す方式は取らない。
3. 生成した画像を `canvas.toBlob`（または `OffscreenCanvas.convertToBlob`）で `Blob` にする。
4. 端末への保存は、`<a download>` による保存、または Web Share API を使う。iOS Safari では挙動が異なるため、実機テストで確認する。
5. 保存処理にネットワーク通信は含まない。生成した Object URL は使用後に解放する。

## 6. 座標系と単位

- **画面座標**：キャンバス左上を原点、単位は CSS ピクセル。タッチ操作はこの座標系で受け取る。
- **キャラクター座標**：画像の中心を原点とする正規化座標を基本とする（詳細は Phase 2 で `types/` に定義）。
- **クリップ座標**：WebGL の標準（-1 〜 1）。変換は `rendering/` の内部に閉じ込める。
- `devicePixelRatio` を考慮し、キャンバスの内部解像度と表示サイズを分けて管理する。
- 保存時の出力解像度は、プレビュー解像度とは独立して決める。

## 7. エラー処理とリソース管理

- 非同期処理（`getUserMedia`、画像デコード、`toBlob`）は、すべて失敗時の処理を持つ。
- ブラウザ API は、使用前に存在を確認する（`navigator.mediaDevices`、`WebGL2RenderingContext`、`createImageBitmap`）。
- 解放が必要なリソースは、解放責任のモジュールを決める。

| リソース | 解放責任 |
|---|---|
| `MediaStream` のトラック | `camera/` |
| `ImageBitmap`、Object URL | `image/`、`capture/` |
| WebGL のテクスチャ・バッファ・プログラム | `rendering/` |

- ユーザー向けのエラーメッセージは `ui/` が表示する。他モジュールはエラーの種別を型で返すか、例外を投げる。

## 8. テスト容易性

- `transform/` と `filters/` の定義部分は、DOM・WebGL に依存しないため、Vitest（node 環境）で検証できる。
- `camera/`、`rendering/`、`capture/`、`image/` の一部は、ブラウザ API に依存するため、実機テストで確認する。
- ブラウザ API に依存する部分は、判定や変換のロジックを純粋関数として切り出し、その部分を単体テストする。
- 詳細は `docs/TEST_PLAN.md` を参照する。
